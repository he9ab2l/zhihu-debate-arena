## 作品简介（约 100 字）

面对职业、学习和生活选择时，我们往往不缺观点，缺的是观点之间的结构。知乎思辩台调用知乎开放平台站内搜索，将内容摘要与原文入口整理成证据卡，再通过“立论—攻防—终局”三回合交锋，帮助用户看见支持与质疑背后的隐含条件。它不替用户投票，也不伪造来源，最终只留下能结合个人处境执行的检查清单。

## 产品亮点

1. **真实来源。** 站内搜索、热榜和额度均接入知乎开放平台 HTTP API，证据卡保留原文链接。
2. **不冒充立场。** 产品将两侧称为“支持视角”和“质疑视角”，避免把摘要强行归因给作者。
3. **诚实降级。** 无 Access Secret 时仍可体验完整产品结构，但明确标注演示模式，不补写虚构内容。
4. **从观点到行动。** 输出可逆性、安全垫、低成本试验、止损线等决策前检查条件。
5. **线上可用。** 已部署响应式 Web Demo，服务端密钥、数据库、登录和 API 层均有明确边界。

## 演示路径

打开在线 Demo 后，可以按以下顺序演示：

1. 点击输入框下方的推荐议题，展示结构化输入体验。
2. 点击“开始拆解”，展示辩题标题、双方主张与三回合交锋。
3. 切换“攻防”和“终局”，展示不同阶段的判断问题。
4. 点击“证据库”，展示真实模式下的来源字段与原文链接；当前无凭证时展示不伪造的空状态。
5. 点击右下角“数据源”，展示连接状态与额度边界。
6. 点击“今日热榜”，说明热榜只负责发现议题，不会自动消耗搜索额度。

## 真实性说明

当前公开 Demo 若未配置 Access Secret，会显示演示模式。这是有意设计，而不是功能缺失：为了遵守知乎开放平台的权限和来源边界，产品不会使用虚构的知乎回答来制造“真实感”。提交评审时，可在部署环境的服务端 Secret 中配置真实凭证，然后重新生成一个议题，即可展示真实 `zhihu_search` 返回的证据卡。

## 参赛视频口播文案

这是知乎思辩台。当你面对一个没有标准答案的选择，它不会替你投票，而是先把分歧摆在桌面上。输入议题后，系统优先调用知乎开放平台站内搜索，将可核验的摘要、原文链接与作者信息整理成证据卡。观点会进入立论、攻防、终局三回合；支持与质疑被放在同一张桌面上，但不会冒充原作者立场。如果没有 Access Secret，系统明确进入演示模式，不伪造论据、不显示估算额度。最后留下的不是替你做好的结论，而是一张行动前检查清单：损失是否可逆，安全垫够不够，能不能先做一个低成本试验。知乎思辩台，把观点交锋变成自己的判断条件。
