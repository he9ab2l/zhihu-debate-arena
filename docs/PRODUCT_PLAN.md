# 知乎思辩台 · 产品说明计划书

## 一、产品定位

知乎思辩台是一款面向学习、职业与生活选择的证据驱动决策工作台。它把知乎社区中分散、异质、带有个人经验色彩的讨论转换成可核验的阅读结构：先呈现支持与质疑两种产品阅读视角，再通过“立论—攻防—终局”暴露隐含前提，最后留下可以结合个人处境执行的判断条件。

产品不追求替用户找一个脱离语境的标准答案。产品要回答的是：**在什么资源、时间、风险和退出成本条件下，这个选项值得被尝试。**

在线作品入口为 [https://link.heabl.xyz/zhihu](https://link.heabl.xyz/zhihu)。

## 二、用户问题

用户在知乎搜索职业、学习或人生选择时，常遇到四类障碍。第一，结果数量多，但支持与质疑观点分散。第二，高赞内容不必然适合自己的阶段与资源。第三，搜索摘要容易被误读成完整回答。第四，读完大量内容后，用户仍然不知道下一步应该验证什么。

知乎思辩台将问题拆为三层。证据层保留检索摘要与原文入口。交锋层把不同选择背后的前提放在同一张桌面上。行动层把判断转译为低成本试验、时间盒、止损线与复盘点。

## 三、用户与使用边界

首批用户是处于选择节点的学生、初入职场者、转行者与独立创作者。他们愿意阅读长内容，但缺少时间把多种经验整理为可比较的判断框架。

访客可以浏览系统已经保存的真实辩题、证据卡和三回合内容。访客不能发起新的知乎搜索。登录用户才可以进行新的议题拆解。所有成功拆解结果都会保存，并显示在左侧“我的辩题”历史列表中。

## 四、核心流程

| 阶段 | 用户行为 | 系统行为 | 可信边界 |
| --- | --- | --- | --- |
| 浏览 | 查看历史辩题或热榜 | 展示已保存真实结果 | 不生成演示来源 |
| 登录 | 完成登录 | 建立可追踪的操作会话 | 当前使用 Manus OAuth；知乎 OAuth 接口待凭证联调 |
| 输入 | 输入不超过 120 字的议题 | 检查登录状态与参数 | 未登录直接阻止检索 |
| 检索 | 点击开始拆解 | 服务端调用知乎开放平台 | Secret 不进入浏览器 |
| 保存 | 查看结果 | 保存结构化辩题与证据元数据 | 无来源或空结果拒绝保存 |
| 研读 | 切换三回合、证据库和热榜 | 独立滚动内容区与右侧抽屉 | 摘要不是全文，提供原文链接 |
| 总结 | 选择单篇、整场或三回合 | 调用 AI 生成严格边界的中文总结 | 不补造事实，不替用户决策 |

## 五、产品设计原则

**来源优先。** 每张证据卡保留知乎原文 URL，并明确标注为检索摘要。

**不伪造。** Access Secret 缺失、接口失败、额度耗尽或搜索为空时，产品不会生成演示辩题，也不会补写虚构作者、赞同数、回答或额度。

**视角不冒充立场。** “支持视角”和“质疑视角”是产品组织材料的标签，不是原作者自称的立场。

**登录后检索。** 访客只读，登录后才能消耗知乎搜索能力并保存新的拆解结果。

**可逆试验。** 最终检查清单优先落到小规模验证、时间盒、止损线和复盘点。

**AI 有边界。** AI 只总结当前真实证据。AI 输出与原始证据分开显示，并提醒用户打开原文核验。

## 六、交互与布局方案

桌面端采用“左侧历史、中间工作台、右侧按需抽屉”的结构。左侧历史支持折叠，折叠后保留打开入口。中间的支持/质疑卡仅承担视角对照，不再使用过宽的 VS 占位。三回合内容使用独立滚动区域，避免整个页面无限拉长。热榜、证据库、数据源和 AI 总结均使用有实体背景的右侧 Sheet。

移动端不同时显示两套侧栏折叠按钮。顶部只保留一个侧栏入口，历史在抽屉中显示。右侧面板宽度适配屏幕，长证据内容在面板内部滚动。

## 七、技术与安全方案

前端使用 React 19、Vite、Tailwind 4 和 tRPC 11。服务端使用 Express 4、Node.js 和 Drizzle。持久化使用托管 MySQL/TiDB。知乎开放平台请求全部发生在服务端，采用 Bearer 鉴权和请求时间戳。AI 服务采用 OpenAI-compatible Chat Completions 接口。

AI 请求会裁剪标题、作者、摘要和回合文本，避免把重复全文送入模型导致超时。服务端设置合理请求超时，并把缺少配置、网络失败、HTTP 错误、空响应和超时转换为用户可理解的状态。

数据库保存辩题元信息、结构化 JSON 和证据元数据，不复制知乎全文。Secret 由托管平台管理，不写入 GitHub，不写入日志。

## 九、评审指标

短期关注登录后首次拆解成功率、真实来源完整率、证据卡原文打开率、三回合完成率和 AI 总结成功率。中期关注历史辩题复访率、同一用户二次拆解率，以及用户对“我更清楚下一步该验证什么”的主观评分。

## 十、风险与对策

知乎内容具有时间性和个人经验偏差。产品不把高赞视为真理，并保留发布时间、来源字段和原文入口。开放平台可能存在额度与频率限制，因此产品采用按需请求、明确的额度面板和安全错误状态。AI 可能产生过度概括，因此提示词要求按证据 ID 标注，明确写出证据不足，并禁止补造事实。
